# Specification procedure

1. Establish feature identity and a repository-relative artifact directory.
2. Load the specification role, constitution, active waivers, relevant
   learnings, and only source evidence needed for this feature.
3. Separate facts, assumptions, decisions, and open questions.
4. Write user scenarios, testable requirements, acceptance criteria, failure
   behavior, data/accessibility needs, risks, and out-of-scope boundaries.
5. Ask product questions only when the answer changes behavior or scope.
6. Record clarification sources as human or reasoned resolution.
7. Validate required sections before handing the artifact to the coordinator.
