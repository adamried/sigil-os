# Discovery

Use for a new, empty, or directionless repository.

Sequence:

1. frame the problem, target users, and measurable outcome;
2. discover business, platform, budget, time, compliance, and team constraints;
3. inspect any existing repository evidence without assuming a stack;
4. compare two or three viable stack approaches using current evidence;
5. write `.sigil/project-foundation.md`;
6. create or revise `.sigil/constitution.md` through a review checkpoint;
7. create `.sigil/project-profile.yaml`;
8. route the first approved feature into Quick, Standard, or Enterprise.

Ask only questions whose answers change product scope or risk. Resolve purely
technical defaults when evidence is sufficient, and explain them in plain
language. Discovery never installs dependencies or scaffolds application code
without a separate implementation request and normal approval handling.
