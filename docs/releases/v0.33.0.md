# Sigil OS v0.33.0 — The Buddy + Design Context Release

> **Released:** 2026-06-01
> **Theme:** Bring sigil-os to parity with the gb-code-buddy fork (v0.39.0) on execution features and design context — and lay the groundwork for the PM Copilot and PO Buddy companion plugins.

This is the biggest Sigil release since v0.30. It adds three major capabilities — autonomous execution, the verified-commit git workflow, and a design context system — plus a half-dozen smaller features that make day-to-day work smoother.

---

## What's New

### Autonomous Execution Mode

You can now ask Sigil to run a feature end-to-end without per-step prompts. Set this up once:

```
/sigil:config set execution_mode autonomous
```

Sigil will confirm with you the first time you enable it (autonomous is more powerful than the default "automatic" mode, so it's not silently switched on). From then on, when you run `/sigil:draw "<feature>"`, Sigil works through specification, planning, tasks, implementation, QA, code review, and security review without stopping to ask "ready to proceed?" between phases.

**Sigil still pauses for safety**, regardless of mode:

- Constitution violations
- Security blockers (Critical or High findings)
- Code review "Request changes" with blockers
- QA fix loop exhaustion
- Out-of-scope file changes
- Override expirations
- Fatal errors

At the end of an autonomous run, you get a **cumulative diff review** covering every change on the feature branch. Accept all, show the full diff, roll back to a specific commit, or pause for manual review.

**Requires the technical track.** Autonomous is for users who are comfortable reviewing a full diff at the end rather than approving step-by-step.

### Verified Commits + Per-Task Commits

The full pipeline now manages git for you in a structured way:

1. A **feature branch** is created before any code is written. Naming follows your constitution Article 2 if defined, else `sigil/<feature-name>`.
2. After each task's QA passes, a **per-task commit** lands. Out-of-scope file changes are surfaced — you decide whether to include, stash, or discard them. No silent inclusions.
3. After code review passes and (if security-relevant) security review passes, the security agent writes `.sigil/specs/<feature>/security.md`.
4. The orchestrator then emits a feature-level **`verified: <feature> security pass`** commit referencing the security report. This commit type is new.

Quick Flow features explicitly opt out — no security review, no verified commit. Quick Flow is for genuinely simple work where this rigor would be overhead.

`tasks.md` gains a **Feature-Level Status** table tracking QA / code review / security review / verification commit as separate gates from per-task status.

### Three-Layer Configuration

Sigil now reads configuration from three layers, in cascade order:

1. **Built-in defaults**
2. **Global** — `~/.sigil/config.yaml` (your preferences across every Sigil project on your machine)
3. **Project** — `.sigil/config.yaml` (overrides for this project)

Project wins over global wins over defaults.

Common new flows:

```
# View your config (shows where each value comes from)
/sigil:config

# Set a preference globally — applies to every project
/sigil:config set --global execution_mode autonomous

# Override just for this project
/sigil:config set user_track technical
```

If you previously had a `.sigil/config.yaml`, it continues to work unchanged — the new global layer is purely additive.

### Design Context System (Optional)

`/sigil:setup` gains a new optional step 5.6 for design teams. Two independent opt-in prompts:

- **External design skills** — register community-authored design guidance repositories as advisory context. Synced into `.sigil/design-skills/` with a 30-day refresh.
- **`.sigil/design.md`** — your project's normative design source-of-truth (color, typography, spacing, components, accessibility tokens). UI tasks load this file at the start of every run. Backend tasks pay zero overhead.

The system uses **deterministic gates** (pure regex + glob, no LLM call) to decide if a task is UI work. When a task would create a brand-new UI component, the developer agent halts and hands off to the UI/UX Designer instead of inventing one.

When agents observe drift between your code and `.sigil/design.md` during a task, they surface a **propose-and-confirm patch** at task end. You accept (writes to design.md after a final diff confirmation), reject (drops to `.sigil/tech-debt.md`), or edit first. **design.md is never auto-edited.**

**Critically: decline is absolute.** If you say no at setup, no command will re-prompt you. The only way to re-engage is `/sigil:design enable`.

Mobile and web profiles are both first-class — no reduced fallback for web.

Manage the system with `/sigil:design`:

```
/sigil:design                      Regenerate .sigil/design.md
/sigil:design list                 Show registered skills
/sigil:design add <url-or-path>    Register a skill
/sigil:design suggest              Show curated examples (with non-endorsement disclaimer)
/sigil:design enable / disable     Toggle the system
```

### Eight New Commands

#### Standalone pipeline stages

Use these when you want one stage without the full pipeline:

| Command | Use it when |
|---------|-------------|
| `/sigil:spec` | You want to write or manage a specification on its own, without auto-running through implementation |
| `/sigil:tasks` | You have a `plan.md` and want it broken into tasks |
| `/sigil:review` | You want code or security review on demand, against current changes or a spec path |
| `/sigil:export` | You want a stakeholder-friendly summary of a feature (separate from the engineer-targeted `/sigil:handoff`) |

#### Companion entries (shorthand)

Terser invocations for the most common day-to-day actions:

| Command | What it does |
|---------|--------------|
| `/sigil:dashboard` | Read-only project overview |
| `/sigil:status` | Read-only mid-workflow status |
| `/sigil:continue` | Resume current workflow |

`/sigil:draw` remains the recommended unified entry. These are companions, not replacements.

### Shared Context Now Uses `gh` CLI

The shared-context system (cross-repo learning sharing, standards inheritance) has migrated from GitHub MCP to the `gh` CLI. This is simpler to set up and works without an MCP server running.

**If you're new:** install `gh` from [cli.github.com](https://cli.github.com), run `gh auth login` once, and `/sigil:connect` will guide you the rest of the way. You'll also need `jq` (most systems have it; `brew install jq` if not).

**If you previously configured GitHub MCP:** nothing breaks. The `.mcp.json` entry remains for backward compatibility during the transition.

For private shared repositories, additionally run `gh auth setup-git` once so git operations reuse your `gh` credentials.

### Code Reviewer Is Now a Dedicated Agent

The code-reviewer was always supposed to be a dedicated agent, not a directly-invoked skill. Sigil had both files but the orchestrator was bypassing the agent. v0.33 fixes this: code review now flows through the Code Reviewer agent (which uses its skill internally). Same verdicts, same checklist, same waiver awareness — cleaner routing.

### Smaller Quality-of-Life Improvements

- **Greenfield profile interview** — when you start in a directory with no source files, `/sigil:profile` skips auto-detection and walks you through six questions about your stack. Useful for new projects where you haven't decided on a framework yet.
- **Preflight skill-resolution hint** — Sigil now tells Claude exactly where to find each skill (`${CLAUDE_PLUGIN_ROOT}/skills/<category>/<name>/SKILL.md`), eliminating multi-minute filesystem searches.
- **Dynamic QA fix limits** — fix-loop iteration limits (5 for full pipeline, 1 for Quick Flow) are now defined in the QA Engineer agent. Projects can override per track via `qa.fix_attempts.<track>` in config.
- **Audit log moved to per-session files** at `.sigil/audit/<timestamp>_<feature-slug>.md`. Legacy single-file logs auto-migrate on first audit interaction.
- **`/sigil:audit` gains 5 new subcommands**: `latest` (default), `list`, `trace <session>`, `agent <name>`, `events <type>`.
- **Output formats centralized** — all visual format templates live in `sigil-plugin/templates/output-formats.md` instead of being duplicated across commands.
- **Routing extracted to a skill** — trigger words and natural-language patterns now live in `routing-rules` SKILL.md as a single source of truth.

### Multi-Plugin Infrastructure

Even though PM Copilot and PO Buddy aren't shipped yet, the scaffolding is now in place:

- `shared-references/` — single source of truth for files shared across plugins (Validated Spec template, communication style, business case, design ticket, story decomposition).
- `scripts/sync-references.sh` — distributes shared files to each plugin's `references/` directory at build time. Supports `--check` mode for CI.
- `scripts/bump-version.sh` — atomically bumps a plugin's version in `plugin.json`, `marketplace.json`, and the README badge.
- `.github/workflows/lint.yml` — workflow linter + sync-references check run on every PR and main push.

## Upgrade Steps

### From v0.32.0

1. **Update the plugin:**
   ```
   /sigil:update
   ```
   Or, if you originally installed manually:
   ```
   claude plugin uninstall sigil
   claude plugin install sigil@sigil-os
   ```

2. **Start a new Claude Code session.** The preflight hook runs and bumps your `SIGIL.md` to enforcement version 2.5.0 automatically (adds the Skill Resolution hint and new phase rows).

3. **Optional: enable autonomous mode.** Only if you're on the technical track and want fewer interactive checkpoints:
   ```
   /sigil:config set user_track technical
   /sigil:config set execution_mode autonomous
   ```
   You'll get a one-time acknowledgement prompt.

4. **Optional: opt into design context.** If you didn't set this up during a fresh `/sigil:setup`, run:
   ```
   /sigil:design enable
   /sigil:design
   ```
   The generator walks you through it. Decline at any point and Sigil won't re-prompt.

5. **Optional: migrate shared context to gh CLI.** Existing GitHub MCP setups keep working, but if you want to retire the MCP server:
   - Install `gh` and `jq` if you haven't already
   - Run `gh auth login`
   - For private shared repos, also run `gh auth setup-git`
   - Your next `/sigil:connect`, `/sigil:learn`, or session-start pull will use the new path automatically

### From earlier versions

Upgrade to v0.32.0 first (it introduced the `/sigil:*` command namespace and is a prerequisite for any features here). The v0.32.0 release notes cover the migration.

## Breaking Changes

- **None for users of `/sigil:draw` workflows.** Existing automatic and directed execution modes behave identically. Autonomous is purely additive.
- **Skill invocation:** Direct calls to the `code-reviewer` skill from outside the Code Reviewer agent are no longer supported. If you have a custom workflow that read `skills/review/code-reviewer/SKILL.md` directly, update it to read `agents/code-reviewer.md` instead.
- **Audit log location:** New entries land in `.sigil/audit/<session>.md`. The previous single-file log auto-migrates on first audit interaction (the original is preserved as `.sigil/audit-log.md.migrated`).

## Known Limitations

- **Mobile + web profiles are both supported**, but multi-profile projects (a single repo targeting both mobile and web) currently pick one. Multi-profile is a future enhancement.
- **External design skills are advisory only.** When they conflict with `.sigil/design.md`, design.md wins. This is intentional — design.md is your project's normative source-of-truth.
- **Net-new component detection uses globs.** If your project uses unconventional layouts (e.g., `**/Views/**`), override via `.sigil/config.yaml` `design.component_globs:`. Default globs cover React, React Native, Vue, Svelte, SwiftUI, and Flutter.
