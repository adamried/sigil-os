# Sigil OS v0.33.1 — Cost-Optimized Agent Models

> **Released:** 2026-07-07
> **Theme:** Route each agent to the model that fits its job — expensive judgment where it counts, efficient execution everywhere else.

A tuning release. No new features, no breaking changes. Agent behavior is unchanged; only which Claude model runs each agent has been remapped so that pipelines cost less to run without weakening the quality gates.

---

## What Changed

Each Sigil agent declares a model in its definition. When `/sigil:draw` delegates work to an agent, Claude Code runs it on that model regardless of your session model. The mapping is now:

| Agent | Before | After | Rationale |
|-------|--------|-------|-----------|
| **task-planner** | sonnet | **opus** | Task breakdown quality determines everything downstream — this is the highest-leverage thinking in the pipeline. |
| **developer** | opus | **sonnet** | With rich specs and Opus-authored task lists, implementation executes against explicit acceptance criteria. |
| **qa-engineer** | opus | **sonnet** | Validation checks work against documented criteria, not open-ended judgment. |
| **orchestrator** | opus | **sonnet** | Routing and state tracking is mechanical coordination. |
| **architect** | opus | opus | Unchanged — technical design is judgment-heavy. |
| **code-reviewer** | opus | opus | Unchanged — the quality gate that catches cheaper-model implementation mistakes. |
| **security** | opus | opus | Unchanged — never cut corners on security review. |
| business-analyst, task-planner¹, uiux-designer, devops | sonnet | (see above) | Unchanged except task-planner. |

¹ task-planner moved sonnet → opus.

## Design Principle

The pattern is **expensive thinking, efficient typing, expensive checking**:

- Planning and task breakdown get the strongest model, because a good breakdown makes the rest routine.
- Implementation, QA, and orchestration run efficiently against that breakdown.
- Code review and security review stay on the strongest model, because they are the safety net for everything produced more cheaply.

## Upgrade Notes

- Nothing to configure. The change takes effect for any session that delegates to Sigil agents after updating.
- To get model routing, work must be **delegated** to agents (Task tool with `subagent_type`), not adopted inline. Inline agent-behavior adoption runs on your session model.

## Compatibility

- No changes to skills, commands, chains, templates, or the constitution format.
- `ENFORCEMENT_VERSION` unchanged (SIGIL.md content is identical).
- Fully backward compatible with v0.33.0 projects.
