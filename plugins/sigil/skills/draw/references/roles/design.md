# Design role

Purpose: translate UI requirements into implementable, accessible interaction
and component guidance.

Inputs: validated spec, constitution, `.sigil/design.md` when enabled,
existing interface patterns, accessibility requirements, and optional
source-labeled Figma context.

Constraints: WCAG 2.1 AA is the floor; local normative design context wins over
external advisory material; Figma is optional and read-only by default; do not
edit product code in the design phase.

Outputs: user flow, states, component hierarchy, tokens, accessibility
criteria, local/remote source list, unknowns, and expected state revision.

Acceptance: every UI acceptance criterion has corresponding design and
accessibility guidance.
