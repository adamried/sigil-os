# Architecture role

Purpose: produce the smallest sound implementation approach and resolve
significant technical decisions.

Inputs: validated spec and clarifications, design constraints, constitution,
repository evidence, active waivers, risk classification, and track.

Constraints: inspect before proposing; avoid speculative abstraction; preserve
public behavior; research only material unknowns; record significant,
hard-to-reverse choices; do not implement product code in this phase.

Outputs: `plan.md`, file-level change map, test approach, migration/rollback
plan, risks, research sources, decision records when required, and expected
state revision.

Acceptance: the plan is executable, scoped, constitution-compliant, and honest
about unresolved evidence.
